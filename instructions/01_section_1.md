## D. Amendments to Section 1 steps

### 1.1 Config
- `test_dates_parse_and_are_quarter_ends`: OPEN-30 B. Every `[sample]` date parses. `first_holdings_date`, `last_holdings_date` and `last_return_date` are calendar quarter ends. `price_end_exclusive` minus 1 day equals `last_return_date`.
- Entities load into a dict keyed by entity id, preserving file order (akre, jensen, polen, ivv, iwf).

### 1.2 EDGAR client
- Signature per OPEN-06. A request counts towards the interval when it is sent, not when it returns.
- Retry on HTTP 429 and 500 to 599 only. Any other non-200 raises at once with the status code and URL in the message.
- The fake clock replaces `time.monotonic` and `time.sleep` in `attrib.edgar` through monkeypatch. `test_min_interval_respected`: 3 back-to-back calls, the recorded sleeps sum to 2 × 0.2 = 0.4 within 1e-9. `test_429_then_200_retries_with_configured_waits`: responses 429, 429, 200 give recorded backoff sleeps [2, 4]. `test_three_failures_raise`: 4 responses of 503 (1 try plus 3 retries) raise, with backoff sleeps [2, 4, 8].

### 1.3 13F parsing
- **Fixture download.** Add `--stage fixtures` to `scripts/pull_data.py` in this step. It writes `tests/fixtures/13f/akre/2023-06-30_0001112520-23-000013.xml` (the information table of that accession) and the Akre information table for period 2022-06-30, whose accession it finds with `list_13f_filings` (the original 13F-HR for that period). Step 1.4 extends the same stage with the IVV fixture. Record each fixture's URL and sha256 in `tests/fixtures/FIXTURES.json`. This is the only network use in steps 1.3 and 1.4.
- `list_13f_filings` takes forms `13F-HR` and `13F-HR/A` only. `amendment_type` is read from the filing's `primary_doc.xml` (local name `amendmentType`) for `/A` filings and is blank for originals. `infotable_name` comes from `find_infotable_name`, which raises if the index holds 0 or more than 1 XML file other than `primary_doc.xml`.
- `period_date` is the submissions JSON `reportDate`. `filing_date` is `filingDate`.
- `parse_13f_infotable` keeps every row, including put/call and PRN rows, with `put_call` blank when absent. Filtering happens only in `resolve_13f_books`. `shares` is `sshPrnamt` as a float. `value_raw` is the integer as filed.
- `units_check` uses kept rows with `shares > 0`.
- Additional test: `test_akre_2023_top_rows`. The 5 largest kept rows of the 2023 fixture by `value_usd`, compared with literal values that you read from the fixture XML and write into the test. The reviewer checks those literals against EDGAR independently.

### 1.4 N-PORT parsing
- `list_nport_filings` reads the atom feed and pages with `&start=` in steps of 100 until a page has no entries. Columns per FILINGS_NPORT; `period_date` is blank in the listing and is filled from `repPdDate` once the file is parsed.
- The IVV fixture is the NPORT-P whose `repPdDate` is 2023-06-30, saved as `tests/fixtures/nport/ivv_2023-06-30_<accession>.xml`.
- `parse_nport`: `balance`, `valUSD` and `pctVal` as floats. `cusip` is the `cusip` element; if it is absent or `000000000`, it is blank. Rows with a blank CUSIP are dropped in `resolve_nport_books` and their value is reported in coverage as dropped.
- Additional test: `test_ivv_fixture_shape`. On the fixture, kept rows number between 495 and 510, and the kept `pctVal` sum lies in [98, 100.5]. Print both numbers in the review.

### 1.5 EDGAR pull
- The 13F pull downloads information tables only for filings with `period_date` in H, plus any `/A` filing for those periods.
- The N-PORT pull downloads every NPORT-P in the series feed filed from 2019-04-01 to 2026-09-30, parses each, and keeps periods in H (Section 3.3).
- `series_resolved.csv` columns: entity, ticker, cik, series_id, class_id.
- If the atom feed for a series returns no entries on its first page, stop under rule 4 and write 2 options in the status file: (a) the EDGAR full-text search API, (b) the trust's submissions JSON filtered by downloading each NPORT-P header.

### 1.6 Holdings and coverage
- Produced by `scripts/run_all.py --section 1` (OPEN-01 B).
- `coverage.csv` row order: entity in config order, then period_date ascending. `lag_days` = filing_date minus period_date in calendar days. For N-PORT rows `median_implied_price` is `val_usd / balance` over kept rows.
- The units check of kickoff 5.1 applies to 13F books only. For N-PORT books, the check is instead that kept `pctVal` sums to within [95, 101] in every period. Stop under rule 4 otherwise.
